# gate: sha256

> Part of the [gate of 2026-11-01](../gate-2026-11-01.md). Rerun the repository's own benchmark with the command in its [README](https://github.com/Kronuz/sha256#-performance). `$GATE` below stands for the gate's working directory (rigs, scripts, micro-benches and raw outputs), which was not kept.

Status: **measured on both machines, 4 rounds each.** **FASTER on the hex string API, SAME on the kernels**: M4 geomean 1.411, i9 geomean 1.112
over the library rows (kernel rows 1.00 on both, `SHA256` hex rows 1.04x to 4.1x); no row below 0.97 on either machine.

characters per byte instead of `+=` per character). The kernels (`sha256_arm.cc`, `sha256_x86.cc`, `sha256_kernels.hh`) are byte-identical
to START. The endian pin moved from `f6269f0` (START) to `8db745f` (HEAD): the A build is given START's pin (`gate-pins.py`).

## Correctness changes that affect comparability

None: the hex output is identical (differential test against the byte-at-a-time conversion, lengths 0 to 300); digests and kernels are
unchanged. CHANGELOG: `SHA256` on 16 bytes 252 to 60 ns on the M4 Pro; measured here 254.6 to 62.0 ns. The 4x of the M4 is the hex
conversion next to a fast SHA2 kernel; on the i9 the portable kernel dominates the call, so the same fix gives 1.46x.
