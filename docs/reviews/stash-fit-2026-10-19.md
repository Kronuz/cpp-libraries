# Where stash fits (2026-10-19)

A read-only fit check of Kronuz/stash against the stack's timer and deadline needs, at stash main
2908b48 and the `fix/descent-window` branch (9e2ebd8). Nothing was built or benchmarked; "by layout"
means computed from the struct and template definitions.

## Corrections to the starting assumptions

1. **Cancel is not in stash, and it is cheap only in time.** stash has no remove, cancel or
   reschedule. The dead flag is the scheduler's: `ScheduledTask::clear()` is one CAS plus a
   `steady_clock::now()` read, and the stash entry is untouched. The walk drops a dead entry only
   when it reaches its slot at the original deadline, so a cancelled timer holds its slot, its heap
   box and its task for the whole remaining delay; `clean` frees structure once `first_valid` passes.
2. **stash has more users than the logger.** Xapiand's committer, `trigger_replication`,
   `db_updater`, `schema_updater`, `settings_updater` and `primary_updater` are scheduler debouncers
   (`src/database/handler.h:331`, `src/manager.h:329`, `src/server/discovery.h:192-216`). Each touch is
   cancel, a new task, and an add: cancel churn, already in production.

## Capabilities

| Question | Answer |
|---|---|
| Layout and horizon | Leaf, then `50x1ms`, `10x50ms`, `36x500ms`, `4800x18s`; exactly 24 h. `add` rejects keys at or past `base18s(first_valid) + 86,400 s`; past the horizon it throws, and `SchedulerQueue::add` silently drops the task. A stalled producer pins `first_valid` and shrinks the horizon. |
| Resolution | 1 ms (the lowest level's Div); a slot drains whole, so an item can fire up to one finest slot early (from reading `next()`; no test asserts it). |
| Cancel | One CAS and a clock read; no structure touched. Dead entries pending ≈ cancel rate × remaining delay; `peep` rescans dead entries ahead of the first live one. |
| Reschedule later | `clear()`, a new task, `add`: one CAS, one or two allocations, a 4-level descent, one dead entry left. |
| Reschedule earlier | `add` the same task again; the one-shot claim makes the later copy a no-op. |
| Insert cost on record | `bench/RESULTS.md` (M4 Pro, before the announce fix): depth 1,024, p50/p99 167/417 ns at 1 thread, 459/1,375 ns at 14; 14-thread p99 1.4-1.8 µs from depth 64 to 16,384, against 65 µs to 1.2 ms for a locked heap and Asio. Arming only; no benchmark covers cancel, reschedule or memory. |
| Memory per context | `StashContext` about 4.3 KB on the branch (64 cache-line announce slots and the handshake fields), about 64 B on main; `SchedulerQueue` holds two. |
| Memory per wheel and item | Top chunk 38.4 KB, allocated on first insert and kept; about 160 B per distinct 1 ms slot in use; per item an 8 B slot, a `shared_ptr` box (16-32 B) and the task. About 47 KB before any timer. |
| Producers | Any number, lock-free; thousands of items in one ms slot degrade an insert (`slot/Size` hops). More than 64 in flight at once share an overflow counter. The scheduler's `add` takes its mutex and notifies when the task is due before the recorded wakeup. |
| Walker | Exactly one thread runs `walk`, `peep` and `clean`; the scheduler wakes at the earliest live deadline, or every 30 s when idle. |
| Ordering | Ascending by finest slot; arrival order within a slot; overdue keys are filed at the last walk's end. |
| Dead-entry churn | No cap or back-pressure. Arithmetic, not measured: 100,000 touches/s on a 3 s timeout leaves about 300,000 dead tasks pending, arguments pinned. |

## One more level (to about a year)

`StashSlots<_4800_18s, 367, 86,400 s, 367>`: Div 24 h, Mod 367, keys below `first_valid + 366 days`.

1. Context memory: unchanged (independent of depth).
2. Wheel memory: a 2.9 KB top chunk, and one 38.4 KB 18 s chunk per distinct day in use (two across
   midnight); a smaller `Size` on that level trades memory for insert hops; `clean` frees past days.
3. Walk cost per refresh: unchanged (one seq_cst store and 64 loads per finest slot); a walk call
   recurses one level more.
4. Descent and the announce handshake: one more level; the handshake doesn't depend on depth.
5. The scheduler's 24 h geometry is a documented invariant, so a longer horizon is an opt-in policy
   with today's as the default; add a `try_add` returning bool before relying on it.
6. Year-scale deadlines must survive restart, so the wheel becomes a cache of persisted deadlines,
   re-armed at open. Where only the horizon is missing, a caller can hop: arm for the next 23 h and
   re-arm on fire.

## Verdicts

| Candidate | Verdict | Today, and benefit |
|---|---|---|
| strata refresh interval (1 s, to 30 s under debt) | Fits with changes | One shared wheel per host, an injected clock, `weak_ptr` payloads, arm on dirty and re-arm on fire; benefit unmeasured, and a mutexed heap would do at modest rates. |
| strata checkpoint thresholds | Doesn't fit | Size and debt triggers, no deadline. |
| strata `sync_interval` (100 ms) | Doesn't fit | One barrier deadline per core, owned by its executor. |
| strata merge-debt checks | Doesn't fit | One controller tick per host (`reactor::PeriodicTimer`). |
| strata idle-index close | Doesn't fit; use `lru-cache` | An LRU of open indexes; every access resets the deadline, stash's worst case. |
| consensus election and heartbeats | Doesn't fit | Host-driven `Tick`, deadlines as `Core` fields, no producers; an additive `next_deadline()` plus an executor-owned heap is what's missing. |
| reactor and http deadlines | Doesn't fit | Asio timers on the owning loop; almost every deadline is reset before it fires. Negative benefit. |
| Per-document TTL | Doesn't fit, even with a level | Format 13's `date` slot, TTL as a filter, a replicated delete on drop. |
| Time-windowed retention | Fits with one more level | Dozens to thousands of timers, days to months out; re-arm from persisted bounds at open; leader only. Reuse, not speed. |
| Cache TTLs | Doesn't fit; use `lru-cache` | `aging_lru` trims passively; one more level only for active expiry callbacks past 24 h. |
| threadpool delayed tasks | Not applicable | Neither branch has delayed tasks; delayed tasks are the scheduler's. |
| Xapiand debouncers | Already on it; better with a lazy re-arm | Store the latest arguments and target deadline; the one pending task re-adds itself when it fires early, so dead entries drop to zero. A scheduler change; unmeasured. |
| logger deferred logging | The reference fit | Many producers, one fire thread, nothing cancelled. |
| cluster Raft and bus timers | Doesn't fit | `reactor::PeriodicTimer` on a single-threaded loop. |

The timer mechanisms stay separate by who arms, who fires, and how often cancel happens: the
scheduler on stash, Asio and `PeriodicTimer`, `aging_lru`, consensus `Tick`, strata `sleep_until`. The
duplication to avoid is a second cross-thread wheel inside strata or consensus.

## Changes it points at (none made)

1. scheduler: lazy re-arm in the debouncer; `SchedulerQueue` geometry as an opt-in policy; `try_add`
   returning bool; clock injection for strata's deterministic executor.
2. consensus: `next_deadline()` on `Core`.
3. Measure before relying on them: cancel, reschedule and dead-entry memory under churn, and the
   announce cost per `add`.
