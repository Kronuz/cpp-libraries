At `radix-router:affe67e`, `radix_router.h:278-288` tries each segment boundary for every nonfinal catchall, recursively trying its continuation. Nested catchalls revisit the same failing suffix states. Static inspection identifies a valid pattern family that can trigger the same repeated work: `/*a/*b/*c/*d/*e/*f/*g/*h/*i/*j/z` against a path of repeated `/x` segments with no final `/z`. This family is a proposed bounded regression; it has not been executed as a new measurement here. The retained fuzz cases also reach partially constructed routes after an invalid insertion throws.

Prevalidating insertions would address partial construction but would not bound matching for valid nested catchalls. A follow-up should preserve match priority and capture selection while avoiding repeated failed `(node, remaining suffix)` states. Memoizing failures is one candidate; its storage and allocation costs need review against the reusable-Params lookup contract. Establish a bounded regression first, then validate the chosen mechanism under sanitizer fuzzing before spending the remaining CPU-hour budget. This requires a matcher design change rather than a harness timeout adjustment.

## Reproduction

The exact build commands are in each build job's spec and `fuzz/README.md`. A bounded continuation reuses the named checkout slot and its accumulated `.scratch/fuzz/corpus`:

```sh
quiet check
campaign job submit --repo "$PWD" --commit HEAD --level light --minutes 30 \
  --slot codex-parser-fuzz-REPO --env FUZZ_CHUNK=N \
  --what 'C4 REPO CPU-hour fuzz chunk N' -- \
  sh fuzz/run.sh build-fuzz/fuzz/TARGET_fuzzer .scratch/fuzz 1700
```

`REPO` is the repository name; `TARGET` is `http_parser`, `base_x`, `boolean_parser`, `cuuid`, `datetime`, `strict_stox`, or `radix_router`. The runner copies stable seeds into the retained corpus and records final executions, coverage, artifacts, and CPU time. The prior queued second and third chunks were canceled before running and provide no evidence.
